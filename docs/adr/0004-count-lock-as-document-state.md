# 盘点锁不建物理锁表，"盘点中"状态的盘点单本身就是锁

盘点单进入 COUNTING(15) 状态即对"该仓库 × 行内 SKU 集合"形成范围硬冻结：所有出入库单据（含采购入库、销售出库、调拨、期初、销售订单审核）在审核时用一条 EXISTS 查询校验，命中即拒绝；范围重叠的第二张盘点单不允许开始盘点；单据离开 COUNTING（审核/取消）锁自动解除。

## Considered Options

- 独立锁表（warehouse_id, sku_id, lock_type）：需要维护加锁/解锁/泄漏清理三套逻辑，与盘点单状态双写可能不一致。状态派生锁零存储、零清理、不可能泄漏。

## Consequences

- 盘点锁（范围级硬冻结，禁审核）与订单锁定（数量级软占用，只减可用量）是两个完全不同的概念，代码与文案不得混用"锁"字语义，见 GLOSSARY。
- 盘点快照 book_qty 取实际库存（不减锁定量）；盘亏后可能出现可用量为负（locked_qty > qty），仅预警不阻断。
- 并发 ≤50、盘点单极少，EXISTS 校验成本可忽略；若未来规模上去，再考虑物化锁表。
