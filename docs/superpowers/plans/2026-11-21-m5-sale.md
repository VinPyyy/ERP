# M5 销售链路 实现计划

> **面向 AI 代理的工作者：** 必需子技能：executing-plans 内联执行。步骤用复选框跟踪。

**目标：** 报价→销售订单（审核锁库存）→销售出库（锁定转实扣，超发严禁）→销售退货（SN 回库）四单据 + 锁定生命周期 + 端到端闭环验收 + 前端四页 + 冒烟。一期验收标准在本里程碑达成。

**架构：** 完全复用 M4 采购骨架与教训（条件状态 UPDATE、原子 done_qty、源绑定审核复核、AUDITED-only 配额、草稿可作废、仓库数据权限、`{doc,items}`+枚举名契约）。库存动作只走 `StockService` 门面——锁定原语（`lock/unlock/release/available`）、SN 翻回（inbound 遇 OUT 态 SN 自动置回）、冲正（`reverse`）在 M3 已实现并测试，M5 是业务组装层。事件走 `DocEvent` 基类（发布无监听）。

**技术栈：** Spring Boot 3 + MyBatis-Plus（sal_* 表已在 V1，零迁移）+ Sa-Token（sale:* 权限点 1201-1220 已种子）+ ApplicationEventPublisher；Vue3/Element Plus。

**规格：** `.scratch/erp-phase1/spec.md` §2.5 sal 表、§3b SN 核销/回库、§3d 盘点锁（含销售订单审核）、§3e 锁定生命周期、§4.1/§4.2 时序、§5 端点表、§8-1/5/6/11/13 裁决 + `issues/06`；前置 `docs/inventory/stock-model.md`、`docs/purchase/purchase-chain.md`（状态机纪律 §1）。

## 全局约束

- 状态机：DRAFT(10)→AUDITED(20)→COMPLETED(30)/VOIDED(50)，行 line_status 10/30/40，全部条件 UPDATE（0 行→10002）。
- 契约教训内建（M4 审查批的裁决直接生效，不留同类缺陷）：page 返回实体（状态=枚举名）、get 返回 `{doc,items}`；审核时复核源绑定（源单状态/仓库/行归属/SKU）；退货配额只计 AUDITED 单；草稿可直接作废（不 reverse）；出库方向批次仅 `LotApi.find` 既有批次、禁 materialize；done_qty 用条件原子 UPDATE。
- 仓库数据权限（spec §5）：四单据 page 过滤 + get/audit/void/create 校验可见；报价 convert 目标仓校验。
- 锁定不变量：每个动锁/动库存的用例收尾断言 `locked_qty = SUM(remain_qty) GROUP BY warehouse,sku`（StockInvariantAsserter 扩展，任务 1）。
- 超发严禁（§8-5）：有源出库行 `qty ≤ 订单行(qty−done)` → 50001；仓库不一致 → 50002；溢收比例不适用销售。
- 每用例 `StockInvariantAsserter.assertConsistent()`；TDD 红→绿；`mvn test`+`npm run build`+冒烟落地。

## 审查重点（Review Focus）

1. **锁定不变量每个节点**：审核锁/部分出库核销/行关闭/整单作废/出库作废重锁——五处各断言 `locked=SUM(remain)`，任何一处漏断言即可能静默漂移 → 任务 3/4 用例族。
2. **出库作废重锁撞可用量**：出库后库存又被直接出库消耗，作废需重锁原核销量 → `lock()` 抛 STOCK_NOT_ENOUGH、整单回滚（裁决：提示先作废下游，逆序哲学）→ 任务 4 `voidOutboundRelockBlockedWhenAvailableEaten`。
3. **超发边界**：qty=剩余放行、剩余+0.0001 拒 50001、多张出库分批累计不穿 → 任务 4 `overShipBoundaryAndCumulative`。
4. **returnable-sns 多轮往返**：出库→退货→同 SN 再出库→再退货，可退集合按最近出库（out_doc 指向最新单）→ 任务 5 `returnableSnsFollowLatestOutboundRoundTrip`。
5. **负库存开关矩阵**：`stock.allow.negative=true` 时订单审核可锁超实存、直接出库可出负——两处行为都要钉 → 任务 3 `allowNegativeLockMatrix` + 任务 4 `allowNegativeDirectOutbound`。
